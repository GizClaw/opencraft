# Code Review

When activated:

1. Read the target files or documents first; review the actual code, not just the summary.
2. Check correctness, security, error handling, edge cases, and consistency with repo conventions.
3. Lead with the verdict, then list concrete issues with file references; separate blocking issues from suggestions.
4. Verify claims against the code before reporting them; never guess.
